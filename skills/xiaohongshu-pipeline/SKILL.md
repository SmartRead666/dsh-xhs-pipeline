# 小红书多账号内容流水线

一套可复用的「内容 → 配图 → 排版 → 定时发布 → 互动监测」工作流。**一个人一条流水线，一个账号一个浏览器目录。**

## 什么时候用

- 用户给一份内容表 / 选题清单，要按天产出小红书图文并定时发布；
- 用户要统一视觉（封面风格、配色、字体）做多天内容；
- 用户要监测某个账号的评论/私信并及时提醒；
- 用户要把同一套方法复制给团队其他账号使用。

## 前置（每台电脑只做一次）

```
python scripts/setup.py                     # 装 playwright、下载字体、建目录、生成 config.json
python scripts/login.py --account <slug>          # 扫码登录创作中心（发布用）
python scripts/login.py --account <slug> --main   # 扫码登录主站（评论/私信用）
```

- 需要本机安装 **Google Chrome**（脚本用 `channel="chrome"`，不下载 Chromium）。
- 字体只用 **得意黑** 和 **思源宋体/黑体**（都是 SIL OFL，可商用）。不要用系统自带的方正/华文商用字体。
- 登录态保存在 `<home>/profiles/<slug>/`，**不要把该目录发给任何人**。

## 工作流

### 1. 写一天的内容 JSON

参考 `examples/day01.json`，必填字段：

| 字段 | 说明 |
|---|---|
| `no` / `date` / `slug` | 第几天、日期、英文短名（用于目录名） |
| `style` | 封面风格，见下方风格表 |
| `h1` / `h2` | 封面两行大字，`h2` 里可用 `<span class='hl'>关键词</span>` 做高亮 |
| `sub` | 封面一句话（可含 `<br/>`） |
| `facts` | 底部三个数据，`[["5"," 层追问"],...]` |
| `photo` | 实拍图文件名（放在 `<home>/photos/`），只有实拍风格需要 |
| `q` / `ch` / `qd` / `st` / `cta` | 5 个内页：问题 / 方法步骤 / 判据四格 / 一句话 / **结尾（做方法收束，不写领取）** |
| `post` | 标题（≤20 字）、正文（≤1000 字）、话题标签、置顶评论 |

### 2. 出图

```
python scripts/render.py --account <slug> --day examples/day01.json
```

输出到 `<home>/output/<slug>/<NN_date_slug>/`：6 张 3:4 图（2160×2880）+ `post.md` + `publish.json`。

出图前会**自动跑合规自检**（见下文第七章），block 级风险会中止出图；确认无误才加 `XHS_FORCE=1` 强出。

### 3. 定时发布

```
python scripts/publish.py --account <slug> --day <目录名> --time "2026-11-10 17:30"
```

- 自动上传 6 图、填标题正文、逐个输入 `#话题`（会转成真话题）、开定时发布、设时间、提交。
- 如果平台弹「扫码验证」：脚本会提示 `NEED_VERIFY`，窗口里用小红书 App 扫码，最长等 5 分钟。
- 退出码：`0` 成功 / `2` 需要登录 / `3` 扫码超时 / `1` 其他失败。

### 4. 互动监测

```
python scripts/monitor.py --account <slug>
```

输出 `<home>/output/<slug>/互动监测/latest.md`，标准输出末行 `NEW` / `NONE`。

## 封面风格表（12 套）

| 代号 | 名称 | 类型 | 适合 |
|---|---|---|---|
| A | 黑底大字报 | 纯文字 | 冲击力最强，干货/方法 |
| B | 米白宋体 | 纯文字 | 杂志感，专业作者 |
| C | 克莱因蓝 | 纯文字 | 潮牌感，年轻受众 |
| D | 实拍压图 | 实拍 | 全幅照片 + 白字 |
| E | 黑金宋体 | 纯文字 | 高端发布会感 |
| F | 正红大字报 | 纯文字 | 最炸眼，避坑清单 |
| G | 左文右双图 | 实拍 | 文字区 + 两图拼贴 |
| H | 上图下文 | 实拍 | 最稳，信息流辨识度高 |
| I | 渐变字 | 实拍底 | 金句/观点 |
| J | 上图下色块 | 实拍 | 硬题、反白强调 |
| L | 杂志封面 | 实拍 | 权威感、整幅照片 |
| M | 双图拼贴 | 实拍 | 两图对比 |

**排期建议**：10 天里 4 条实拍 + 6 条纯文字，轮换测试，10 天后按曝光/点击率/涨粉挑 2–3 套固化。

## 账号与运行安全（内容合规见上一章）

1. **不承诺就业、接单、收入**；案例与照片需授权脱敏；价格班期只指向官方号。
2. **一个账号一个浏览器目录**，绝不共用 profile；**不要在一台机器/一条网络上高频跑多个号**（易被判矩阵号）。
3. 发布节奏：每号每天 1 条、固定时间；连续提交 4–5 条会触发扫码验证，属正常风控。
4. 草稿/登录态目录（`profiles/`、`_work/`）**不对外分享**。
5. 自动化有风险：发布前人工确认内容，失败要人工介入，不追加重试到触发封禁。

## 内容生成铁律（写文案前先读，这章比排版重要）

小红书的驳回几乎都来自**同一个模式：用利益换互动**。平台 AI 会在发布后几分钟内扫图和扫文，
命中就「不被推荐给未关注用户」，等于白写。所以生成内容时就要避开结构，而不是发出去再救。

### 一、四条红线（来自真实驳回记录）

| 类型 | 平台原话 | 踩雷写法 | 安全替代 |
|---|---|---|---|
| **诱导互动** | 「以互动方式获得资源、物品」 | 评论【关键词】领取××表；评论区留言领模板；扣1领；关注领资料 | 只做方法分享，把讨论留在评论区，不给资源换互动 |
| **图片换评论** | 「图片中诱导评论领取模板…属于用模板换评论，违规」 | 末页写"评论 xx 领走模板" | 末页只写方法收束或行动建议 |
| **引导去图片找资源** | 「正文引导用户去图片里找资源，配合图片构成违规」 | "配图里的三问可以直接拿去问客户" | 删掉这类句子，正文自身把方法讲完 |
| **站外导流** | 禁止联系方式与二维码 | 加微信、公众号、二维码、手机号 | 想深入聊就写"不方便公开的可以私信" |

另外两条会限流但不会直接驳回：**绝对化用语**（最好/第一/唯一/100%）、**效果承诺**（一定/立刻见效）。

### 二、CTA 怎么写才安全（先选一种，再动笔）

| 类型 | 写法 | 例句 |
|---|---|---|
| **讨论式** | 问一个用户答得出的具体问题 | 「你手上这个场景，卡在数据还是卡在负责人？」 |
| **判据式** | 给判断标准，让读者自己对照 | 「三条里中两条，就值得先做一个两周的验证。」 |
| **行动式** | 收在一件今天就能做的事 | 「今天就挑一个流程，把三问过一遍。」 |
| **边界式** | 先说不适用的情况（专家感最强） | 「需求还说不清的阶段，别急着做方案。」 |
| **私信式** | 允许私信，但不承诺资源 | 「不方便公开说的可以私信，我按情况给判断。」 |

**禁用清单（末页和正文都不要出现）**：领取 / 领走 / 送模板 / 关键词 / 暗号 / 扣1 / 关注领 / 评论区留言领取 / 私信领取。

### 三、正文骨架（照着填就有专家感）

```
① 反常识判断（1 句）      —— 先否掉一个常见做法
② 3-5 个可执行条目        —— 每条带判据，不写形容词
③ 一个真实约束            —— 成本/组织/数据，体现做过项目
④ 边界话（1 句）          —— 什么情况下不适用
```

示例（Day1 痛值愿正文）：
- ①「客户说想用 AI，我先不急着接」
- ②「痛：谁痛、痛在哪、多久发生；值：省多少时间降多少错误；愿：愿不愿调流程给数据」
- ③「只有痛没有值，容易做成公益项目」
- ④「三问都过，才进入方案阶段」

**写作禁忌**：形容词堆砌（赋能/闭环/抓手）、感叹号、emoji 轰炸、通篇排比、"家人们"式口语营销。

### 四、标题与话题

- 标题 ≤20 字，用「反常识 + 具体对象」：`AI场景不是越多越好`、`MVP不是做个半成品`
- 标题不要出现：领取、免费、福利、最强、保姆级
- 话题 5-8 个：1 个品牌词 + 2-3 个行业词 + 2-3 个长尾搜索词；不要塞无关热词

### 五、发布前自检（机器 + 人工）

```
python scripts/compliance_check.py <内容JSON或publish.json>
```

`render.py` 出图前、`publish.py` 发布前都会自动调用；有 block 级风险会中止（退出码 4）。
人工再过一遍这 10 条：

1. 有没有「评论/留言/关注 + 领取/送」的组合？
2. 末页有没有出现"领取/关键词"字样？
3. 正文有没有"配图里有 X，可以拿去用"这类句子？
4. 有没有微信/公众号/二维码/手机号？
5. 有没有承诺就业、接单、收入、效果？
6. 有没有绝对化用语（最/第一/唯一/100%）？
7. 标题是否 ≤20 字、无营销词？
8. 话题是否 5-8 个且相关？
9. 案例与现场照片是否已获授权脱敏？
10. 价格、班期、团报是否已移除（只指向官方号）？

### 六、被驳回后的处理 SOP

1. 手机 App 打开通知 →「笔记审核详情」→ 看**存在问题**和**AI 智能分析**（它会直接指出哪张图、哪句话）
2. 按 AI 分析逐条改：图片里的诱导文字、正文里的引导句，两类都要改
3. 改完重新出图 → **删除旧笔记** → 重新发布（旧笔记留着也只会被限流）
4. 同批内容整体复查：同一个模板通常会带同一批文案，一篇被驳回，其他篇大概率同款

### 七、判断标准：什么叫"专家感"

不是术语多，而是**具体到能反驳**：

| 弱 | 强 |
|---|---|
| AI 项目要重视需求调研 | 客户说"想用 AI"，先问三个问题：谁痛、值多少、愿不愿改流程 |
| 做好 MVP 很重要 | MVP 只做一件事：验证"这个场景真的有高频使用" |
| 要关注 ROI | ROI 算四项：省的成本、增的收入、降的风险、总投入 |

写完自检一句：**这段话能不能被具体反驳？** 不能反驳的就是正确的废话，删掉。

## 故障处理

| 现象 | 处理 |
|---|---|
| `NEED_LOGIN` | 跑 `login.py --account <slug>` 扫码 |
| `NEED_VERIFY` 一直超时 | 换时间再试，或减少当日提交条数 |
| `TIME_FAIL` | 检查时间格式 `YYYY-MM-DD HH:MM`，必须是未来 1 小时 ~ 14 天内 |
| 发布后笔记管理看不到 | 到创作中心「笔记管理」确认是否进入审核 |
| 主站监测报登录失效 | 跑 `login.py --account <slug> --main` |
| 图片字体不对 | 检查 `config.json` 的 `fonts_dir`，或重跑 `setup.py` 下载字体 |
